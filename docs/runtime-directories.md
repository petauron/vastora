# 受管运行目录生命周期

关联：Vastora #356。运行目录属于 Vastora 或已安装套件的资源，用户安装后不应手工创建目录、配置 tmpfiles 或修改服务文件。

## 责任划分

| 资源 | 声明和所有者 | 创建与恢复 | 移除 |
| --- | --- | --- | --- |
| `/run/vastora`、Caddy Admin socket | Vastora 共享网关，固定路径 | 安装器自动注册开机准备单元；在 Docker 和 Agent 之前准备 root:root/0700 目录。Agent 启动也按同一安全规则核对 | 所有容器挂载引用解除后，完整卸载才移除受管单元、已核对的 socket 和空目录 |
| `/run/vastora-pkg-*` | 签名套件与受管服务实例 | Vastora 为每个原生服务生成 `RuntimeDirectory`/0700，包括没有凭据的服务；配置和凭据从持久来源通过 `LoadCredential`/启动前复制恢复 | systemd 在服务停止时处理临时目录；卸载由套件回执核对身份后移除服务，持久数据按明确的删除选择处理 |
| `/run/vastora-deployer` | Center 安装器创建的共享 Docker 命名卷 | 卷不依赖宿主 `/run` 中的空目录；Deployer 启动时创建目录、核对并重建自己的 Unix socket | 由 Center 完整卸载流程按卷归属处理 |
| `/run/vastora-caddy` | Vastora 原生共享 Caddy | 已有受管 unit 使用 `RuntimeDirectory`，Caddy 从独立持久配置/证书存储恢复 | 原生共享运行时保留最后一个使用者之前的公共程序和数据 |
| 容器内 `/run/vastora-credentials` | 签名套件和 Docker 执行器 | 使用受管卷或受管配置注入，不据容器内路径推断宿主文件系统的生命周期 | 沿用套件回执和现有卷清理规则 |

## 安装和升级

共享目录的开机单元是 `vastora-runtime-directories.service`。它由 Vastora 自动生成、验证归属并启用，只创建本产品固定的共享运行目录；不连接 Center、不修改 Docker、不领取任务，也不重放网关配置。它在本地文件系统就绪后、sysinit/Docker/Agent 启动前运行，目录不会随 Agent 普通重启而被删除。

Center 安装和升级在 `compose up` 前，用已验证的目标镜像内程序准备目录，避免 Compose 自动生成错误权限的挂载源。临时程序不会被写入开机单元；正式主机程序安装后再注册持久单元。已有 Agent 在新版本启动时自动补齐注册，不要求重新接入或管理员补系统配置。

Agent 和 Deployer 复用同一目录校验：拒绝符号链接、非目录、不可信所有者、可写祖先和不符合要求的目录/socket 权限；不自动接管或修改陌生资源。Deployer 在停止原网关前完成校验。

目录准备后，具有 Docker 能力的 Agent 在首次连接 Center、启动任务循环之前，限时核对已有 Caddy 和 HAProxy 的网络附件。恢复组件归属和原网络声明均匹配的受管容器，等待原绑定地址就绪，沿用原容器 ID、端口和别名并读取实际结果。对于 Docker 自动启动时因原声明地址尚不存在而失败的网关，仅在 `unless-stopped` 策略、退出码 128、原绑定地址的 `cannot assign requested address` 错误均吻合时，核验已有网桥并启动同一容器，再恢复附件。缺失容器、正常停用、端口占用及未知退出原因不授权启动；网桥缺失、归属异常或自定义网络参数无法复现时停止恢复并报错。该步骤不重载配置、不改写已应用修订，也不重放应用任务；后续心跳和断线重连仍只观察状态。

Caddy 健康检查同时核对实际网络端点和发布端口，不能仅凭 Unix Admin socket 可访问就报告网站网关健康。网络恢复失败不会阻断 Agent 的管理连接，但心跳继续报告实际运行状态，供明确的受管操作处理。

安装注册失败会撤回新增单元或恢复原单元；主机程序安装回滚时同步撤回本次新增的开机注册。Agent 更新继续遵循已有数据库迁移边界，不因目录恢复失败自动回放任务或降级数据库。

## 共享与卸载

套件卸载沿用现有共享 Caddy 站点/系统路由归属机制，不直接移除平台共享目录。完整卸载在删除主机程序前，检查所有容器（包括已停止容器）的挂载引用；还有引用、Docker 无法核对、单元被修改或目录内存在未知文件时保留资源并报出原因。只删除已验证的 socket 和空目录，不递归清理 `/run`。

待人工核验任务仍按原保护处理。准备目录不等于重新执行或确认该任务，也不等于应用已经通过启动预热、网站、REALITY 或订阅访问验收。
