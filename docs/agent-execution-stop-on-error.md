# Agent 执行与出错停止（#412）

## 当前 MVP 契约

Center 持久保存任务、一次性授权、任务摘要、尝试、进程会话、结果及处置审计；Agent 仅在内存中管理当前执行。已有实现由 #429 交付，后续更新助手结果归属见 [更新恢复说明](agent-update-recovery.md)。完整 Agent 长期低内存验收和专用缺失证据/凭据轮换界面仍按 [MVP 交付范围](agent-execution-delivery-audit.md#mvp-发布范围以用户最新决定为准) 延后。

## 授权与结果

- 任务选择和一次性执行授权在同一 Center 事务中提交；加密或提交失败不产生可执行任务。
- Agent 必须取得 start、step 及续租的确认后推进。HTTP 错误、心跳失联或授权失效取消当前执行；停止不撤销已经发生的外部效果。
- 未完成的执行在租约过期或进程会话更换后变为 unknown，保持领取屏障。旧会话不能重新注册，迟到结果不能覆盖新 attempt 或新配置。
- 结果先加密留存，业务投影与执行终态原子提交。Center 已留存、校验通过的成功结果可以完成业务投影；这不调用 Agent，不重新执行管理命令。未知或缺失证据不能据此恢复。
- 连接恢复、心跳及只读观察可以继续；它们不会重新授权失败任务，也不会为了恢复控制连接停止正常运行的其他应用。

## 人工处置

设置页的执行记录提供暂停/恢复领取、详情、确认已完成、明确放弃及重新执行。处置要求管理员确认旧执行已停止并填写核对说明；后端检查权限、任务身份、attempt、最新业务状态和证据，并在同一事务中记录审计。

- 确认已完成：只使用后端能够验证的成功证据，保留原始执行和结果，不调用执行器。
- 明确放弃：保留证据，使匹配的业务尝试终止，不撤销已发生的外部效果。
- 重新执行：核对并处理现场冲突后创建新的有效授权；旧授权不会恢复。
- 旧协议回执只做保密归档与明确放弃，不恢复旧执行协议。

缺少结果、遗留候选容器或备份时，先在维护窗口核对运行时、配置和凭据，再进行处置。按钮不能替代现场核对；不能直接删除数据库或把 unknown 改成成功。

## Xray / Meridian 替换失败

正常替换依次创建候选、准备配置交接、停止旧实例、保留旧实例、启动并验证候选、晋升，最后清理旧实例。各步骤仍使用当前任务 context。

首次变更开始后，创建、停止、改名、启动、校验或清理失败均按不确定结果返回并立即停止。即使错误来自响应丢失，也不继续删除候选、改回旧名称、写回旧配置或重启旧容器。已有容器、加密配置记录、数据库快照和阶段证据保留。重复调用发现中断标记时拒绝继续。

Agent 重启发现 Meridian pending 配置、未完成交接、待退役 gate，或旧 Xray 的 desired/applied revision 不一致时，只报告需要显式恢复，不自动推进配置、启动候选或清理中断容器。恢复已完整应用的健康运行时和监控仍保留；明确卸载但保留数据的应用不会复活。

这意味着失败发生在旧实例已停止之后时，受影响应用可能需要人工恢复才能重新可用。系统不承诺回滚，也不会绕过执行屏障进行自动恢复。

## 更新、安装和迁移材料

更新助手一次性交接，失败或开机均不重跑旧授权；原程序、候选、受保护恢复点和结果材料保留。安装、卸载与迁移按步骤停止，未知结果不会重新排队。Center schema 采用先备份、前向事务迁移和失败关闭；不自动降级。

Agent 旧回执只在任务循环进入时按加密证据归档，Center 确認身份与摘要后才退役本地对应项。当前任务不写入旧回执表，不扫描历史完成队列，也不进行周期历史清理。详见 [旧回执边界](agent-task-receipts.md)。

## 验证记录

2026-10-01 复核并运行以下最小回归：

```sh
go test ./internal/agent ./internal/center \
  -run 'Test(XrayReplacement|XrayConfigurationRestartFailure|RuntimeRestart|Execution|LegacyReceipt|Meridian.*Recovery|ReplaceMeridian|CompletedMeridian|ResumeXray|ControllerConvergenceStops)' \
  -count=1 -timeout=90s
```

- `TestXrayReplacementStopsAtFirstFailure`：旧面板迁移、Xray、Meridian 三种路径，在创建、停止、改名、启动、校验、取消、清理和响应丢失窗口逐项核对变更序列；失败后保留现场，重复调用无后续副作用；成功流程继续完成。
- `TestXrayConfigurationRestartFailureDoesNotRollback`：通过模拟 Docker HTTP API 注入重启响应失败，确认只发出一次重启请求、不写回旧配置、不生成成功应用回执。
- `TestRuntimeRestartKeepsUncertainRevisionBlocked`：重新打开持久 Store 后不推进待处理配置或交接，保留原始证据并上报恢复状态。
- 现有 Execution / LegacyReceipt 测试：授权提交失败、响应丢失、断联、旧会话与 attempt 隔离、失败屏障、人工处置、加密归档、投影原子性及协议前向迁移。

本轮使用隔离测试和模拟 Docker，不声称完成真实宿主故障注入、全量 UI 验收或长期低内存平台期验证。源码、CI、发布与线上版本分别核对。
