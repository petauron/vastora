# Alpha 快速发布边界

维护者明确选择：Alpha 阶段不运行 race，保留普通测试和必要构建。以受检提交的版本号判断阶段，不再使用 `VASTORA_CI_MODE` 开关。统一规则见 [MVP CI policy](ci-policy.md)。

## 必须通过

- PR：Go 格式、API 契约、静态检查、完整普通测试和交叉编译；前端 lint、测试及构建按路径触发；真实主机/网络集成按相关模块触发。版本 PR 在自身准确提交上运行真实 CI 和 CodeQL，另做元数据校验。
- 发布：现有目录信任根预检、amd64/arm64 编译、前端构建、amd64 镜像版本命令启动检查、镜像架构和安装包校验、签名/来源证明、R2 上传与激活后的下载验证。
- 任一步实际执行失败仍阻止对应门槛通过，不将失败伪装成成功。只有明确不适用的检查会跳过。

## 不阻塞 Alpha 发版

Alpha 的 PR、发布前、每周及手动检查均不启用 race。普通测试完整保留，不再重复运行多个重叠用例子集。PR 不再单独构建双架构镜像用于扫描；发布扫描最终镜像。依赖检查按依赖变更、版本 PR 或定时/手动运行触发。CodeQL 保留。旧安装包清理由已有每日 R2 reconcile 任务处理，发版不再等待清理及清理后的重复下载验证。

Alpha 接受并发数据竞争可能漏检的风险，不代表已保证稳定性。Beta/稳定版由同一个测试入口恢复 race。版本命令能启动不代表所有生产业务功能已验证。

## 缓存与耗时

普通测试沿用分离的 Go 模块和编译缓存；保留发布镜像缓存及目录信任预检缓存，不新增缓存层。优先减少重复编译和测试次数。

发布镜像上下文排除 Go 测试源码，修改回归用例不会再使生产源码层缓存失效；测试文件仍完整保留在 Git 和完整 CI 中。

### 减少发布缓存搬运

alpha.127 的日志显示：双架构编译并行约 57 秒；复用 Dante 结果时仍下载了约 228 MB 的构建环境层。优化针对缓存内容和层依赖，不增加共享编译缓存：

- Dante 和前端构建结果先导出到仅包含产物的 `scratch` 阶段；缓存命中时，消费者只需读取小产物层，不必还原 C 工具链或 Node 依赖目录。
- 源码与产物使用 Docker 原生 `COPY --link` 独立层，减少无关父层变化造成的复制缓存失效。参见 [Docker COPY --link](https://docs.docker.com/reference/dockerfile/#copy---link)。
- Go 下载依赖后，在同一个构建层删除重复 ZIP 压缩包，保留解压后的模块、工具链和校验元数据；不删除依赖或关闭校验。
- 现有注册表缓存使用低压缩等级 Zstandard；不新增缓存仓库或 Actions 缓存，也不改变发布镜像的压缩格式。参见 [Docker registry cache](https://docs.docker.com/build/cache/backends/registry/)。

首次构建需要生成新的缓存层，不应拿首次耗时宣称热缓存性能。后续仍需用真实发布日志对比下载/解压、编译和上传时间。版本变化仍需正确编译、链接，未通过复用旧版本二进制来缩短时间。

1～2 分钟是热构建、无排队时的优化目标，不是已验证的承诺。统计应区分 PR 检查、发布构建、上传和排队；冷构建与 GitHub 排队仍可能超过目标。此策略不自动发布每次提交，也不绕过 PR 合并授权或分支保护。
