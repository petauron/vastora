# PR #359 阶段审查

2026-09-08。本记录不是合并批准，也不替代未执行的端到端验收。

## 已修正

- **升级后的安全隔离状态**：历史迁移 56 会将早期安全迁移停止的共享 443 入口改回 pending。
  新迁移 64 只撤回未就绪 guard 的 REALITY 入口，并更新已保存的 Gateway/节点监听任务版本，
  删除其中不安全的路由；健康入口不动。历史迁移没有修改，迁移前备份和失败关闭保留。
  对仍需经过迁移 56 的旧版本，升级前持久化已停止入口的记录，迁移 64 恢复其原状态。
  保留停止原因，并按旧版安全停止原因和拓扑补齐新版本的需处理标记；旧 schema 没有该字段。
  即使中间迁移仍把记录保持为 stopped，也会撤回残留路由，不仅检查状态文字。
  已经经过旧迁移、且没有该记录的安装，无法仅凭 pending 推断历史用户意图，不伪造停止状态。
- **DNS 与端口状态混淆**：节点监听成功不再抹掉尚未解决的 Cloudflare DNS 错误。
  仍须域名与入口检查真正通过，才显示就绪。
- **网络恢复重试**：只自动重接受管默认配置，回读必要别名、端点和发布端口；不复制失效的
  运行时 IP/端点 ID。异常端点若带自定义别名、静态地址、驱动参数、Links、GwPriority，
  则在断开前拒绝。只暂存在内存不足以保护这些信息：断开后进程退出会使重试丢失原配置。
  健康端点不受影响；没有为了支持未知自定义配置增加不持久的恢复分支。
- **落地放行回读**：Linux nft 会省略能从命名 payload 推导的冗余协议条件。
  生成规范形式后继续进行严格比较，没有忽略策略漂移；隔离网络 CI 实测放行过期及重新启动关闭。
- **业务检查**：按当前无密码 Dante 方案使用精确私网来源授权；拒绝意外 UDP relay、仅建立 ASSOCIATE 但无数据、
  错误 DNS 事务/问题/来源以及非公网 IPv4 出口。未运行公网探测或读取线上凭据。
- **原生防火墙**：限定专用 UID 和单个私网来源，解析/DNAT 后再次限制真实目的地址，
  没有通用 established 放行或全机出站变更。已增加隔离内核和实际套接字 CI 用例。
- **CI 覆盖**：增加恢复、迁移、REALITY 和内核放行定向检查。历史版本夹具从旧 schema
  向前升级，不再把当前 schema 改版本号后冒充历史数据库。
