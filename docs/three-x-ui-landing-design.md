# 3x-ui 统一落地 MVP（#353）

状态：开发中，尚未成为可使用的端到端功能。用户已确定落地侧使用 Dante，
无 SOCKS 用户名密码；不得再要求 Docker、3x-ui 面板或原生 Xray。

## 首版交付范围

- Center 选择一台受管机器作为落地机。
- 发布镜像为两个架构编译并嵌入固定版本 Dante；Agent 解包原生程序，配置 systemd、私网监听和必要访问限制。系统软件源负责 nftables 和 libcrypt1，不安装系统 Dante 服务。
- 各 VLESS 节点有一个落地开关；原订阅、客户端身份和公网入口不变。
- 开启后业务通过现有 Headscale/Tailscale 到 Dante，保留 TCP 和 UDP。
- 页面只显示未开启、等待应用、连接正常、连接异常；技术信息不铺在主界面。
- 不做批量操作、SOCKS 密码管理/轮换、复杂恢复向导和容量承诺。

## 不可省略的边界

- 不增加独立 WireGuard，不使用 Tailscale Exit Node，不改变全机默认路由。
- Dante 只绑定自身私网 IPv4。只允许选中的节点地址，默认拒绝其他来源。
  无 SOCKS 密码不等于向整个内网开放；Headscale ACL 和本机来源规则须一致。
- 所有落地业务的 DNS 在落地侧解析。服务使用独立 DNS/NSS 配置，
  不借用主机的本地 DNS stub 绕过内网目的地址限制。
- 专用服务 UID 的出站策略阻断内网、回环、元数据、管理端口与 IPv6。
- 在实际代理 Agent 上检测到 DERP、peer relay、断线、超时或状态不明时阻断业务，
  不自动切回原节点出口。用户已接受检测窗口，不承诺绝对零中转。
- 放行有短期内核有效期，Agent 退出/卡住不能永久放行。
- 修改只作用于选定业务入站，保留安全拒绝规则和无关路由，不改 HAProxy。
- 初始开启失败保留旧配置；写后回读；重试不得覆盖其他操作修改的配置。
- 开机不得先恢复无保护的落地路由。保护失败只能影响选定代理实例，不能阻断整个 Docker。
- 关闭/切换时明确终止选中 3x-ui 实例的旧连接；页面提示该实例会短暂中断。

## Dante 的 UDP

Dante 的 TCP 控制端口为 1080，UDP ASSOCIATE 为每个会话分配中继端口。
首版使用私网 UDP 1081–1208，有界范围同时用于 Dante、来源限制、代理侧阻断及 Headscale ACL。
探测必须核对返回的私网地址和范围，并完成真实 UDP 数据交换，
不能把 UDP ASSOCIATE 返回成功当成 UDP 可用。

依据：[Dante 配置手册](https://www.inet.no/dante/doc/latest/sockd.conf.5.html) 的
udp.portrange 与无认证模式；[进程手册](https://www.inet.no/dante/doc/latest/sockd.8.html)
说明 -V 仅验证配置并退出。
