# 3x-ui 统一落地设计（#353）

状态：**2026-09-07 用户已确认连接检测方案；业务功能尚未实现。**

需求来源：[Issue #353](https://github.com/petauron/vastora/issues/353)。
本文取代此前提出的独立 WireGuard 方案。没有运行本地测试、构建、网络故障实验，
也没有修改生产环境。

## 已确认的架构与安全边界

指定一台受管理节点作为统一落地机，每个 3x-ui 代理节点独立或批量选择
原节点出站、统一落地出站。订阅、客户端身份和公网入口保持不变。
落地机使用原生 Xray SOCKS5 与 systemd，不要求 Docker 或 3x-ui 面板。

业务沿用现有 Headscale/Tailscale 私网。**不增加独立 WireGuard，不使用 Exit Node，
不全局禁用 DERP 或 peer relay，不改变整机默认路由。**
SSH、Komari、Center/Agent 管理通信保持原路径。

已接受的是“检测到中转后阻断”，不是“绝对零中转”：

- 路径切换到检测、阻断完成之间，可能已有业务数据经过中转。
- 发生在两次检查之间的短暂中转可能漏检，不能保证每次切换都能发现。
- 接受检测窗口不代表允许持续使用中转。
- 检测失败、结果过期、断线、DERP 和 peer relay 均不允许继续放行。
- 运行故障只阻断落地业务，不能悄悄恢复原节点出口。

## 如何判定连接

检测必须发生在**每个实际代理节点到落地节点之间**，不能使用 Center 到落地机
的状态代替。由节点 Agent 调用本机 tailscaled LocalAPI，向落地私网地址执行
有超时的 disco ping；不依赖 Center 持续在线才能作出阻断决定。

仓库当前固定 Tailscale 1.102.3、Headscale 0.29.3。上游
[PingResult](https://github.com/tailscale/tailscale/blob/v1.102.3/ipn/ipnstate/ipnstate.go)
提供 Endpoint、PeerRelay、DERPRegionID 等实际探测结果。判定时必须校验
目的节点、探测类型和本次请求的新鲜度：

| 结果 | 连接状态 | 落地业务 |
| --- | --- | --- |
| 本次 disco 响应含有效直连 Endpoint，且没有中转标记 | 直连 | 还需业务健康检查，不能仅凭 ping 放行 |
| 本次响应含 DERPRegionID / DERPRegionCode | DERP 中转 | 阻断 |
| 本次响应含 PeerRelay | 节点中转 | 阻断 |
| 节点明确未连接 | 未连接 | 阻断 |
| 超时、错误、目标不匹配、数据缺失或过期 | 无法确认 | 阻断 |

不能把 status 中的 Relay 字段存在解释为当前正在中转；该字段也可能只是节点
所属 DERP 区域。Online、历史 CurAddr 和单纯 ping 成功均不能替代上述判定。
如果探测结果指向子网路由器而非指定落地节点，拒绝将其视为目标直连。
本机目标也不能伪装成一次成功的远端直连检查。

## 阻断机制的实现约束

仅有周期检查和一个布尔开关不够。业务放行必须有有限有效期，并且在检测程序
退出、停止更新或卡住时自行失效，不能留下永久有效的允许状态。

- 初始状态为阻断；取得新的直连结果和 SOCKS5 业务健康结果后才允许启用。
- 任意不安全或未知结果立即撤销放行，终止受影响业务，不等待下一次 Center 下发。
- 恢复必须重新取得直连和业务健康证据，不能复用持久化的“健康”值。
- 实现必须明确检查间隔、单次超时、放行有效期以及进程退出后的阻断方式。
  具体数值与数据面实现尚未落地，不能当作已有时延保证。
- 只处理受管理的落地业务，不屏蔽整个 tailscaled 的中转连接。
- 保持受影响连接与检测器生命周期绑定，或使用会自动到期的数据面放行。
  在实际实现、审查之前，不宣称已选定的阻断机制能覆盖全部故障。

上游 [addrForSendLocked / send](https://github.com/tailscale/tailscale/blob/v1.102.3/wgengine/magicsock/endpoint.go)
仍可能将业务发送到 DERP；应用层检测不会改变这一机制。
[连接类型文档](https://tailscale.com/docs/reference/connection-types)也说明连接可以
在直连与中转之间变化。该事实是已接受的检测窗口来源，不再作为独立 WireGuard
方案的前置要求。

## 落地服务和配置应用

以下仍是待开发要求，不因放宽零中转要求而取消：

- 原生 Xray SOCKS5 只绑定指定私网 IP，启用认证；来源规则只允许选定代理节点。
  凭据沿用 Center 加密存储、加密任务传输，不出现在日志、任务输出或普通 UI 响应。
- 明确 UDP ASSOCIATE、返回的私网地址和 UDP 端口。TCP 通畅不代表 UDP 可用。
- 业务 DNS 在落地侧解析；目标限制必须在解析后仍有效，阻断私网、回环、
  链路本地、云元数据、管理地址/端口和域名重绑定旁路。
- 明确 IPv6 支持状态；不支持时阻断，不从原节点直接出站。
- 安装、升级和卸载只处理 Vastora 拥有的服务和文件；不删除已有 tailscaled。
  限制日志和资源，不承诺未经测量的 512MB 主机容量。
- 路由只匹配受管理的业务 inboundTag，保留高优先级安全阻断规则、REALITY
  未认证回落、用户自定义路由及 HAProxy。不能用全局 catch-all 代替节点开关。
- 期望状态、已应用版本和运行健康分别记录。开启失败保留旧配置并显示未生效；
  已生效后的故障阻断，不恢复 direct。并发修改、重试和批量部分失败均需明确处理。
- 新增数据库结构使用备份保护的前向迁移，不修改已发布迁移或自动降级。

### 切换旧连接

3x-ui v3.7.0 的
[xray/update](https://github.com/MHSanaei/3x-ui/blob/v3.7.0/internal/web/controller/xray_setting.go)
可能通过热更新应用路由，也可能重启 Xray。API 返回成功不等于原有业务连接
已经终止。实施时需要明确旧连接清理方法；如果只能重启整个实例，必须说明
受影响范围，不能声称无损或仅影响单个入站，也不能重启无关实例。

## 界面和验收

界面配置统一落地节点，提供单节点和批量开关；分别显示等待应用、生效、阻断、
应用失败。检测说明使用“中转后阻断”，不使用“绝不中转”或“严格直连”。

显示连接路径、SOCKS5、TCP/UDP 可用性、实际出口 IP、最后成功时间和失败原因。
未检查显示未检查，不将未知伪装成通过。

验收沿用 #353 全部清单，重点记录直连断开、中转发现、阻断完成的实际时间，以及
检测窗口内可能存在的中转流量；另测检查失败、进程退出、结果过期和恢复。
还需覆盖实际出口、DNS/IPv6、来源授权、目的地址限制、凭据轮换、旧连接、
配置恢复、离线节点、批量部分失败及轻量服务资源占用。

**以上为待实现和待验证要求，不是已完成的功能或已通过的验证。**
按仓库规则，未经用户明确要求不运行本地验证，也不修改线上环境。
