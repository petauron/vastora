# Catalog schema 4 contract

The authoritative protocol, versioned Go module, JSON Schemas, fixtures, source
rules and publisher live in [petauron/catalog](https://github.com/petauron/catalog).
Vastora consumes a pinned module, not a second local protocol implementation or
application recipe list.

This is implementation work, not a production cutover claim. `go.mod` pins
`v0.0.0-20260926153451-7d7df53dd5d4` without a local replacement; the independent
feature-branch PR is still under review. Production gates remain disabled
pending [maintenance acceptance](catalog-release-guide.md).

## Identity and runtime boundary

Package identity is `(source, appId, version, packageRevision)`.
Versions are canonical SemVer without a leading `v`. Changing a previously
published recipe requires a higher positive package revision; old identities
and manifest digests cannot be overwritten. Historical schema 3 manifests
retain their original digest and map to revision `0` for audit and one-time
resource adoption, never an alternate legacy installation path.

Recipes declare `runtime.kind`, `runtime.version` and
`runtime.requiredCapabilities`. Agents report `capabilities.executorVersions`
and `capabilities.runtimeCapabilities`. An unknown runtime/version/capability
blocks that package/node combination, not every valid catalog entry. Ordinary
new applications do not need a Vastora app-ID allowlist or program release.

- Docker declares pinned images, containers, structured arguments, environment,
  secret references, configuration, volumes, private ports, dependencies, health
  checks and resource limits. Arbitrary Compose and shell hooks are rejected.
- systemd declares a verified artifact, executable, arguments, structured
  configuration, credentials, user and state directories. Agent generates a
  constrained unit. Raw units and shell hooks are rejected. Extraction accepts
  only declared regular files, with path/link/size defenses.
- Root, host network, host-path mounts and device access require declared
  capabilities and administrator grants. Upgrades cannot silently enlarge them.

JSON/YAML/env values are structured, not executable templates. Secrets travel
separately; manifests/receipts contain references only. Secret Docker environment
values remain visible to privileged daemon operators, but are excluded from
Vastora logs, views and receipts. Applications bind privately by default;
external Publications remain separate.

## Consumer API

`GET /api/v1/catalog/apps` returns each manifest with `manifestSha256`,
freshness/expiry, install blockers and `managedConfigFields`. Product-managed
fields are generated by Center, not rendered or submitted by the browser;
ordinary applications do not require a product integration.

Install/upgrade requests to `POST /api/v1/deployments` must carry the reviewed
`packageRevision`, `manifestSha256` and explicitly approved
`authorizedCapabilities`. Changed catalog identity invalidates the request.
Omitted grants can retain existing grants, never approve an expansion.
Configuration/uninstall use the recorded installed manifest.

Instance resource records retain real container/volume/unit/path ownership,
artifact and manifest digests, package revision and grants. Uninstall keeps data
by default. Upgrade validates/downloads, consistently backs up, switches, checks
health and commits. Failed migration preserves evidence; it must not restart an
old executable against newer data.

## Standalone tools and private sources

The `catalog` tool comes from the independent module; `vastora catalog` has
been removed. From an independently reviewed catalog checkout:

```sh
go run ./cmd/catalog keygen --out-dir ./catalog-keys
go run ./cmd/catalog validate --catalog ./catalog.json
go run ./cmd/catalog sign --catalog ./catalog.json --private-key ./catalog-keys/catalog-signing-private.key --key-id catalog-key-1 --output ./catalog-envelope.json
go run ./cmd/catalog verify --envelope ./catalog-envelope.json --public-key ./catalog-keys/catalog-signing-public.key
```

Private sources use the schema 4 exact-byte Ed25519 envelope. Verify the decoded
base64url payload before parsing; reserialization is not signature verification.
Only public keys enter Center. The independent module owns schema semantics,
portable fixtures, key validation and signing behavior.

Private HTTPS sources retain bounded downloads/redirects, optional CA and
write-only Bearer credentials, separate from registry credentials. Conditional
requests cannot establish new trust or extend signed expiry. Failed refreshes
preserve verified cache and report staleness. Official `vastora-official` is
reserved and TUF-root anchored. Source deletion/credential changes cannot clear
immutable history or rollback high-water marks. Refresh never upgrades apps.
