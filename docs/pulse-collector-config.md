# Pulse configuration

## Service authentication initialization

The new Pulse Service requires both application fields before installation or
the first upgrade from Alpha.2:

| Configuration key | Behavior |
| --- | --- |
| `public_url` | Required HTTPS browser origin, for example `https://pulse.example.com`. A root slash is allowed; credentials, subpaths, queries, and fragments are rejected. Configure the matching access entry before opening `/login`. This origin is separate from the collector's private HTTPS URL. |
| `setup_token` | Required write-only secret, 32–4096 bytes without surrounding whitespace or line breaks. The operator supplies a private random value and retains it for first administrator setup at `/login`. It has no default and is not an Agent enrollment token or administrator password. |

The existing manifest `secret: true` path separates the token from public
configuration, encrypts it in Center, delivers it through `task.Secrets`, and
retains it in the Agent's encrypted applied state. Configure and upgrade operations
merge the stored encrypted secret when it is omitted; there is no plaintext token
in `task.Config`, ordinary configuration persistence, Docker environment variables,
or task error messages. No token is generated by this integration.

Deployment reuses CPA's in-memory tar-to-Docker-copy pattern, without a shell or
arbitrary file-writing endpoint. Before starting the new container it writes only
`/pulse-bootstrap/setup-token`: its parent is root-owned `0711`, and the file is
owned by `65532:65532` with mode `0400`. The environment contains only
`PULSE_PUBLIC_URL` and `PULSE_SETUP_TOKEN_FILE` in addition to the image defaults.
Archive ownership is retained; Docker's `CopyUIDGID` option is deliberately not
enabled because that would assign the protected parent to the container user too.

This is permission protection in the container's writable layer, **not a read-only
mount** or immutable secret. The owner can change its own file mode, and a Docker
administrator/root remains privileged. The root-owned parent prevents the Pulse
user from replacing the path. No new secret volume, host-side secret directory,
OAuth configuration, or webhook credential is introduced. A failed copy prevents
container start and removes only the newly created container, never its data volume.

Container recreation recopies the retained encrypted token. The existing
`vastora-pulse-data` volume and upgrade-before-migration backup are unchanged;
the token does not reset an initialized administrator or clear the database.
An old installation without these saved fields must provide them explicitly before
upgrading. A matching `/healthz` response alone does not prove that browser login,
Origin/CSRF handling, or administrator setup works.

The checked-in image/version pins still target Alpha.2 and have not been published
or deployed by this change. The new authenticated Pulse image and its normal
catalog release update are required before this integration can be shipped.
Go regression tests cover configuration rejection, encrypted secret retention,
archive ownership/modes, environment secrecy, data-volume preservation, and
copy-failure cleanup. The following checks passed with Go 1.26.6 in an isolated
macOS checkout using separate temporary Go and staticcheck caches:

```text
make go-format-check go-static-check
go test ./internal/pulse -count=1
go test ./internal/agent ./internal/center -run '^TestPulse' -count=1
```

The existing updater-download tests in `cmd/vastora` require a supported Linux
runtime and fail at that platform check on macOS. Linux CI remains required;
these local results do not replace its kernel/systemd/container integration
checks. No live container or browser acceptance test was performed.

## Collector configuration

Vastora manages the Pulse Service URL, Service application ID, node name, and node
group. The application form accepts only the collector's country code and discovery
provider; it cannot change enrollment credentials or redirect a retained identity
to another monitoring Service.

| Configuration key | Behavior |
| --- | --- |
| `node_region` | Optional ISO 3166-1 alpha-2 country/territory code, such as `SG`, `US`, or `HK`. A manual code takes precedence over discovery. An explicit empty string clears a configured country. |
| `geoip_provider` | `geojs` by default; `ipinfo` selects IPinfo; `disabled` disables lookup. |

The metrics interval belongs to Pulse. Vastora does not expose an interval field
or send `PULSE_INTERVAL_SECONDS`; installation and upgrades use the collector's
own default instead of overriding it. Any interval controls supported by Pulse
remain managed in Pulse, not Vastora.

The default GeoJS lookup shares the node's public egress IP and Agent version
with GeoJS, never Pulse credentials or host metrics. Choose `disabled` to opt out;
set a manual country to keep the node positioned on the globe without discovery.

Upgrades retain explicit `PULSE_NODE_REGION` and `PULSE_GEOIP_PROVIDER` assignments
from the existing managed `/etc/vastora/pulse-agent.env` when those fields are
absent from the stored Center configuration. This covers installations configured
manually before these form fields existed. Explicit Center values take priority;
subsequent omitted form values retain the saved configuration. The current generic
form treats an empty input as omitted; the configuration API accepts
`{"node_region":""}` when intentionally clearing a saved country.

The upgrade reader accepts plain values and simple single/double-quoted values,
validates the two settings, and emits a canonical environment file. It never
sources or executes the file, copies arbitrary environment entries, or imports
credentials from it. Invalid/duplicate location assignments fail before changing
managed installation files. The retained environment is limited to 16 KiB.
Restoring a managed installation applies the same location interpretation before
checking the expected file content. Enrollment and retained Agent credentials
continue to use protocol version 2.

These changes target the new Pulse collector implementation. The checked-in
release version, binary URLs, and checksums remain unchanged in this development
branch. Before shipping it, publish the corresponding Pulse release and update
the existing release catalog through its normal workflow; Alpha.2 does not support
automatic country discovery. This work does not implement catalog publication or
automatic release synchronization.
