# 多落地机与应用工作区

## 范围

- 管理员可配置多台落地机（上限 16 台），每个 VLESS 节点选择一台或使用本机出口。
- 保留 Dante、受控私网身份、直连检查和断线阻断；不增加自动故障切换。
- 不修改客户端订阅、公网域名或订阅主机的归属。
- 移除落地机前必须先切换使用它的节点；配置切换未确认完成前也保留旧授权。

## 界面设计

以生成的桌面工作区及侧边面板概念为视觉参考；现有导航保持不变，不仿制 macOS 窗口控制按钮。设计检索没有返回适用的管理界面方案，采用系统设置式的紧凑列表，而非营销页面布局。

| 字号 | 内容 13–14 px，辅助文字 12 px |
| 暗色表面 | 背景 #191c21，面板 #232830，边界 #3b414b |

应用之间切换查看。3x-ui 的订阅主机使用单行工具栏，节点、状态、出口、落地延迟和入口集中在表格；详细配置从行末打开侧边面板。

出口菜单列出每台落地机对应的实测延迟。尚未开启落地时，列表展示当前可直连且延迟最低的一台作为预览，并标注名称；不会自动选择或启用它。无数据时显示待检测，不用估算值。列表与菜单共用一条实时连接，每个检测结果只更新对应的来源节点与落地机组合；配置概览的轮询不覆盖已收到的新延迟。

切换或重试前显示简短确认，说明该节点现有代理连接会短暂中断、订阅地址不变；取消不写入配置。确认期间节点配置版本变化或目标不再就绪时，须重新选择。选择“本机出口”实际恢复开启落地前的完整出口规则，保留原有自定义代理，不承诺必然直出。

选择框表示期望出口，不代表已经生效。切换中、失败或连接不可用时，另显示“上次应用”的出口；该记录只表示最近一次成功回执，不能代替实时健康。正常已连接时不重复显示辅助信息。

## 数据与切换

数据库 67 通过前向迁移将单个已选节点转换为数组，保留原有节点选择与 revision。迁移使用现有备份和失败关闭流程，不提供数据库降级。

数据库 68 保存上次确认应用的落地 ID；空字符串表示恢复原出口，NULL 表示没有足够证据。迁移仅回填期望与已应用 revision 相同且 ready/stopped 的记录，不能从失败或切换中的新目标猜测旧出口。失败和过期回执不会覆盖该记录。API 的 `proxies[].applied` 返回其 revision 与落地 ID，不包含私网凭据或完整 Xray 配置。

新出口的来源授权准备完成后，Agent 先确认直连，再保存路由替换检查点。停止旧监测会重启选定的 3x-ui 实例，因此新检查点在管理接口重新就绪后读取。检查点保留最初的本机出口配置，以及允许替换的上一份完整配置；人工改动仍视为冲突。新门禁先安装为关闭状态，再清理旧门禁。只有当前 revision 成功确认后，Center 才清理旧来源授权。失败时可重试或恢复本机出口。

延迟按来源节点与落地机的组合记录，校验目标身份、配置版本及时间。最多检测 16 个目标，Agent 最多同时进行 4 个只读探测。每个目标独立定时，完成后通过鉴权接口立即上报，不等待其它目标，也不随下一次心跳批量发送；检测与上报不阻塞管理心跳。移除或更换目标会取消旧检测。

Center 复用现有消息通知机制，通过 SSE 首次发送快照，之后只推送变更及过期的组合。页面保留其它仍新鲜的结果，断线时也按各自检测时间在 45 秒后过期；重连收到完整快照。SSE 定期重新建立以重新检查管理员会话，不增加公网探测入口。

接口：Agent 使用 `POST /api/v1/agents/{id}/landing-latencies` 上报单条观测；管理员页面使用 `GET /api/v1/three-x-ui/landing/latencies/events` 接收实时结果。移除原心跳中的批量 `landingLatencies` 字段，心跳仅下发允许检测的目标。

Center、Agent 和前端须一起升级到本功能版本，不保留旧单落地 API。旧 Agent 的心跳字段不再被新 Center 接受，混用版本可能显示节点离线；不能依赖混合版本期间的自动更新完成全部节点升级，应安排同一维护窗口更新所有 Agent。本次代码发布不操作线上实例。
