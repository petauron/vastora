# 多落地机与应用工作区

## 范围

- 管理员可配置多台落地机（上限 16 台），每个 VLESS 节点选择一台或使用本机出口。
- 保留 Dante、受控私网身份、直连检查和断线阻断；不增加自动故障切换。
- 不修改客户端订阅、公网域名或订阅主机的归属。
- 移除落地机前必须先切换使用它的节点；配置切换未确认完成前也保留旧授权。

## 界面设计

以生成的桌面工作区及侧边面板概念为视觉参考；现有导航保持不变，不仿制 macOS 窗口控制按钮。设计检索没有返回适用的管理界面方案，采用系统设置式的紧凑列表，而非营销页面布局。

| 项目 | 约定 |
| --- | --- |
| 字体 | 系统字体栈，macOS 优先 SF / PingFang |
| 字号 | 内容 13–14 px，辅助文字 12 px |
| 暗色表面 | 背景 #191c21，面板 #232830，边界 #3b414b |
| 暗色文字 | 主文字 #f3f4f6，辅助 #b0b6c0 |
| 亮色表面 | 背景 #f5f5f7，面板白色，边界 #dedee3 |

| 间距 | 4 / 8 / 12 / 16 / 24 px；桌面列表常规行约 60 px |
| 延迟 | <20 ms 绿色，20–100 ms 黄色，>100 ms 红色，并始终显示数值 |
| 操作 | 键盘可用的应用标签页与出口选择；移动端触控目标至少 44 px |

应用之间切换查看。3x-ui 的订阅主机使用单行工具栏，节点、状态、出口、落地延迟和入口集中在表格；详细配置从行末打开侧边面板。

出口菜单列出每台落地机对应的实测延迟。尚未开启落地时，列表展示当前可直连且延迟最低的一台作为预览，并标注名称；不会自动选择或启用它。无数据时显示待检测，不用估算值。列表与菜单共用一份轮询数据。

## 数据与切换

数据库 67 通过前向迁移将单个已选节点转换为数组，保留原有节点选择与 revision。迁移使用现有备份和失败关闭流程，不提供数据库降级。

新出口的来源授权准备完成后，Agent 先确认直连，再保存路由替换检查点。停止旧监测会重启选定的 3x-ui 实例，因此新检查点在管理接口重新就绪后读取。检查点保留最初的本机出口配置，以及允许替换的上一份完整配置；人工改动仍视为冲突。新门禁先安装为关闭状态，再清理旧门禁。只有当前 revision 成功确认后，Center 才清理旧来源授权。失败时可重试或恢复本机出口。

延迟按来源节点与落地机的组合记录，校验目标身份、配置版本及时间。每次最多检测 16 个目标，Agent 最多同时进行 4 个只读探测。

Center、Agent 和前端须一起升级到本功能版本，不保留旧单落地 API。旧 Agent 的心跳字段不再被新 Center 接受，混用版本可能显示节点离线；不能依赖混合版本期间的自动更新完成全部节点升级，应安排同一维护窗口更新所有 Agent。本次代码发布不操作线上实例。
