# Agent 更新就绪与下载重试

## 原因与修复

Center 进程已健康不代表提供下载的入口已经完成恢复。原流程在 Center 启动后直接下发 Agent 更新；同机 Agent 随后重建 Caddy/HAProxy 时，会中断正在传输的二进制文件，并将各节点任务直接记为失败。

自动更新继续并行，但下发前检查：

- Center 启动协调已完成、Agent 二进制目录已配置。
- 如有主机更新服务，其操作必须处于空闲或成功状态，不能仍在更新、失败或状态未知。
- 对有托管入口绑定的安装，通过已有节点记录找到该地址唯一、在线的宿主节点；其网关组件、路由和本机监听配置都必须完成当前修订。
- 只等待 Center 宿主入口，不等待其他节点的网关，避免一个无关节点阻塞全体。

没有托管入口绑定的部署不凭空增加网关依赖。检查错误保留为不可下发，不把未知状态当作就绪。

入口后续仍可能因合法配置变更而短暂断开，因此 Agent 下载阶段还提供最多 3 次重试，间隔 2、4、8 秒，总下载预算 2 分钟。复用现有 `go-retry` 依赖，版本不变。

仅重试连接重置、拒绝、断管、超时、响应中途结束及 HTTP 502/503/504；每次重建请求和临时文件，先关闭上次响应并清理未完成文件。身份验证、证书、元数据、完整性、版本检查、磁盘及安装失败不会自动重试。取消请求立即停止等待。所有候选文件仍须通过摘要和版本检查，主机更新恢复/备份流程不变。

## 边界与验证

- 离线节点不会下发更新。更新中途失联后，不再计入正在更新的节点，不阻塞已完成的 Center 更新或后续版本检查；页面单独提示离线节点。已排队、下载中或安装中的任务仍保留，重新上线后沿用原任务处理，不因离线取消安装或重新创建任务。
- 更新进度沿用节点已有的在线判断，不引入新的等待时限。已确认失败的任务仍需手动重试，不因状态展示调整而自动重试。
- 本改动不自动重开已经终态失败的任务，不修改历史错误，也不增加数据库兼容路径或迁移。
- 重试发生在持久化安装交接前，不重复执行安装、重启或已接管的恢复操作。
- 已补充入口修订未完成、主机更新中/失败、离线/多义入口、无关网关故障、断流后成功、重试上限、取消及永久错误不重试的回归用例。
- 按 AGENTS.md，本轮未运行本地测试、构建或静态检查；新增测试命名由现有 CI 的 Agent 更新检查覆盖。
- 线上通过已有管理界面重新下发本次失败任务；12 个启用节点均已报告 alpha.112。该操作恢复的是已发布版本，不代表本文件所述防复发代码已部署。
