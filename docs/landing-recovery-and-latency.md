# 落地切换恢复与延迟

## 路由保存

3x-ui 保存 Xray 配置时会将专用 API 路由移到最前面。落地配置比较只规范化这条精确的 API 规则，保留所有业务规则的顺序和内容；其他差异仍然拒绝覆盖。

配置协调期间，已经运行的 3x-ui 不再先被重启。停机实例只在关闭业务出口的保护下启动管理接口，成功应用配置后才结束旧连接。结束旧连接由同步切换流程负责，随后启动的监控不再重复重启容器；Agent 重启后的恢复仍走同一条同步切换流程。

## 首次启用与诊断

首次启用在修改路由前等待落地端就绪：最多 3 次尝试，间隔 1 秒，准备阶段总预算 30 秒。每次出口 TCP/UDP 检查共用 8 秒预算，前后分别验证私网直连身份；中转或任一业务检查失败不能放行。期间保持应用任务正在调整的状态，不要求用户因一次瞬时失败手动重试。

耗尽准备预算仍失败时不切换原路由。该任务进入失败状态，通过页面「重试」显式重新提交，保留原修订号和加密恢复记录；没有无限后台重试。运行期检查仍为 3 秒，15 秒的出口放行有效期不变，也不会复用较慢的首次检查结果。

首次检查记录尝试次数、阶段、失败分类和耗时；运行期相同的连续探测错误只记录一次，成功后重置。诊断区分 SOCKS 连接、TLS、HTTP 状态/响应、UDP 协商和 DNS 交换等阶段，但 SOCKS 服务端的 DNS 解析仍归入 SOCKS 连接阶段。日志不包含原始远端报错、响应正文、订阅凭据或密钥，页面不增加技术细节。未开启 Dante 业务访问日志，避免记录用户访问目标。

## 节点到落地机延迟

Center 通过已认证心跳向安装了 3x-ui 的受管节点发送当前落地机的私网身份。节点在心跳后执行一次有界 disco 探测，下次心跳上报；不要求开启落地，不安装应用、不修改路由、不授权业务流量。

延迟采用 Tailscale PingResult.LatencySeconds，不以整个 HTTP 请求的耗时替代 RTT。只有经过身份确认的直连结果显示毫秒数；中转或失败显示无法直连，缺少或过期的观测显示待检测。启用时仍须通过原有 TCP/UDP 与直连检查，延迟不等同于业务可用性。

Center 的观测缓存仅保存在内存，按节点和当前选择修订匹配，45 秒过期；重启后等待新观测，不增加数据库迁移。UI 复用已有的落地状态刷新，不为每张节点卡片新增轮询。

## 覆盖范围

回归用例涵盖 API 规则重排、业务规则冲突、终态任务不自动重试、显式重试、首次准备的有限重试与取消、前后直连检查、脱敏诊断、监控不重复切换及退出清理、未启用节点获得探测目标、RTT 提取、中转结果和过期观测。按项目规则不运行本地测试，由 PR CI 执行。
