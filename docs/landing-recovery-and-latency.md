# 落地切换恢复与延迟

## 路由保存

3x-ui 保存 Xray 配置时会将专用 API 路由移到最前面。落地配置比较只规范化这条精确的 API 规则，保留所有业务规则的顺序和内容；其他差异仍然拒绝覆盖。

配置协调期间，已经运行的 3x-ui 不再先被重启。停机实例只在关闭业务出口的保护下启动管理接口，成功应用配置后才结束旧连接。失败任务停止自动重试，通过页面「重试」重新提交；启用重试保留原修订号和加密恢复记录。

## 节点到落地机延迟

Center 通过已认证心跳向安装了 3x-ui 的受管节点发送当前落地机的私网身份。节点在心跳后执行一次有界 disco 探测，下次心跳上报；不要求开启落地，不安装应用、不修改路由、不授权业务流量。

延迟采用 Tailscale PingResult.LatencySeconds，不以整个 HTTP 请求的耗时替代 RTT。只有经过身份确认的直连结果显示毫秒数；中转或失败显示无法直连，缺少或过期的观测显示待检测。启用时仍须通过原有 TCP/UDP 与直连检查，延迟不等同于业务可用性。

Center 的观测缓存仅保存在内存，按节点和当前选择修订匹配，45 秒过期；重启后等待新观测，不增加数据库迁移。UI 复用已有的落地状态刷新，不为每张节点卡片新增轮询。

## 覆盖范围

新增回归用例涵盖 API 规则重排、业务规则冲突、失败不自动重试、显式重试、未启用节点获得探测目标、RTT 提取、中转结果和过期观测。按项目规则不运行本地测试，由 PR CI 执行。
