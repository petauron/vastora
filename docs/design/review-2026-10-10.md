## 范围与环境

本轮按用户要求使用 frontend-app-builder，先逐项打开可用页面，再进行独立只读评审及针对性重构。在独立 UI 工作区中，沿用已有登录页、桌面框选与图标规范。没有修改主工作区或 A1。

浏览器预览使用本机 Vite 与隔离只读 API：13 台虚构主机、7 类目录应用、28 个安装实例；地址为文档保留地址，目录为 example.invalid。所有写入请求拒绝执行。Meridian 使用现有本地 UI 开发模块挂载，非已发布 bundle 验收；独立 Pulse、Telegram Bot 网页不在此次范围。

## 发现与修复

1. 原全高侧栏用于短表单时产生大段空白：共享 Sheet 改为内容自适应居中属性窗口，保留顶/底启动器模型。
2. 长表单与确认框缺少小屏边界：增加视口约束、独立正文滚动、固定头尾与 16px 边距；手机输入、操作及关闭区域至少 44px。
3. 网络节点卡片过于分散：改为名称/状态、能力、地址、操作四区的分隔行，窄窗口换行。
4. 原生 confirm 不符合主题且易与窗口交互割裂：目录删除、未保存编辑、关联节点操作统一为 Base UI AlertDialog，保留警告与明确确认条件。
5. Portal 中的折叠箭头和外链按钮样式不统一：复用全局规则，隐藏浏览器默认 marker，链接继续保留链接语义。
6. 应用详情主操作顺序不一致：调整实际 DOM 顺序，主操作置于次操作之后，视觉与 Tab 顺序一致。
7. 最终独立评审发现同级弹窗的 Escape/焦点风险：二次确认移入所属 SheetContent（form 外），由 Base UI 管理真正的嵌套层级。
