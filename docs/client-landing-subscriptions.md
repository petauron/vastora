# 客户端落地订阅（#409，MVP）

入口：应用 → 3x-ui → 客户端 → 落地组合。

## 首版范围

- 保留原订阅地址和原有节点，为指定客户端增加获准的「入口 → 落地」组合。
- 组合节点使用独立身份；Mihomo / OpenClash 可直接使用自选入口策略，也可同时提供两种形式。
- 各客户端独立授权，入口和落地只从现有受管节点中选择。
- 父账号与组合共用原套餐的流量、到期时间及续期设置，不复制多份免费额度。
- 保留手动停用、删除、撤销和必要的失败重试；撤销不退还已消费流量。
- 新增落地用途支持 TCP/HTTPS，不声明 UDP、QUIC 或 FullCone 支持。既有节点级落地功能保持不变。

## 订阅用法

继续使用原 `/sub/<token>` 地址提供原节点和组合节点。
完整 Mihomo 输出使用同域名的 `/clash/<token>`，或由原订阅路径识别 Mihomo 客户端。

内容复用 3x-ui 原生订阅，在 Agent 内按当前客户端授权补入组合或策略。
无需 Subconverter、额外转换服务、转换后合并命令或配置片段接口。
修改授权时只确认本次实际调整的入口，不保存供未来自动断连使用的授权快照。

## 必要约束

- 凭据和账本加密保存；同名的新账号不能继承旧账号的权限。
- 先确认路由和原生身份更新，再发布组合；部分额度写入沿用已保存的目标重试。
- 套餐按实际到期时间下发，不使用 90 秒短期续约。到期和额度限制复用原生账号限制；按周期续期只推进一次用量基线。
- 手动停用、删除和撤销仍完成必要的路由与身份处理，不影响未操作的授权。
- 保留既有入口到落地的直连检查和故障阻断，不新增 Center 失联时的跨节点账号断连系统。
- 首版不提供共享账本跨订阅主机迁移。仅保留拒绝不安全迁移的检查，避免把部分额度当作新套餐；不将开发迁移系统列为首版待办。
- 数据库仍使用备份优先的前向迁移，不因精简产品范围而删除数据库安全迁移。
