# 永久移除过期节点

适用于到期、不再续费且已经离线的节点。在「节点」卡片选择「永久移除」，输入显示的节点名称确认。

这与「停止接入」不同：停止接入只撤销凭据，永久移除还会清理 Center 内的应用安装记录和关联资源。不是远程卸载，也不等待离线 Agent 回复；离线主机上的程序、文件和第三方应用内部历史数据不在此操作的清理范围内。

## 清理范围

- 撤销旧 Agent 凭据和该节点的重新接入授权，终止该节点的等待或未确认任务。
- 从在线的 3x-ui 订阅主机删除该节点的条目，保留订阅主机和其他节点；收到删除结果后才清理本地关联记录。
- 清理该节点应用的专属访问入口，以及由 Vastora 管理的私网身份、Tunnel 和不再使用的专属凭据。
- 删除该节点的安装、更新、任务和任务事件记录，服务、路由、网关、落地关联及节点记录。保留地区、应用商店目录、共享集成和审计会话。

如果节点仍为其他节点提供订阅主机、落地服务或共享入口，先调整这些依赖。当前 Center 所在主机也受保护，不会通过此操作移除。

## 失败与重试

确认后立即停止旧 Agent 接入，清理进度由 Center 持久保存。刷新页面或 Center 重启不会丢失进度；外部入口清理失败、订阅主机离线或未及时确认时，显示「重试移除」。重试沿用已记录的私网身份与任务，不以同名节点或重新分配的 IP 作为删除对象。

停止接入不表示永久移除已经完成。私网归属校验失败时，后续 3x-ui 节点和应用记录仍会保留；修复后使用「重试移除」继续原任务，不需要重新接入离线节点。私网归属按当前 Headscale API 的 `tags` 中的 `tag:vastora-agent` 判断，结合已确认的受管私网地址和节点密钥校验，不要求带标签的设备归属到某个用户名。

数据库使用版本 74 的前向迁移，复用现有迁移前备份和失败关闭机制。最终关联记录删除在一个事务内完成；未处理的外键依赖会阻止提交，而不是关闭外键强删。

## Glivela 独立接管后的移除

先在独立 Glivela 中停用待退役节点及相关订阅／客户端链式线路；Vastora
不代写 Glivela 业务库，也不把平台移除当成 Glivela 退役回执。共享控制端或
落地仍有其他使用者时，应先由对应业务所有者处理，不自动切换其他线路。

确认全局业务已经完成接管后，永久移除只处理平台生命周期：撤销接入、清理
该节点的专属入口和受管私网／Tunnel，停止它的安装管理。已冻结的旧代理
账本、凭据、历史及其外键引用保留，移除任务以 `complete` 持久结束；该节点
和安装不再出现在正常列表中，旧凭据及重新接入流程不能复活它。未完成接管
时旧 pilot 归属保护仍然有效，不能靠移除绕过。

数据库版本 124 通过现有一致性备份和前向迁移增加内部完成状态，保留已失败
任务和外部清理进度。重试继续同一个任务，不重建私网身份，不删除保护触发器，
也不以删除冻结账本来满足平台外键。生产升级和实际重试需另行授权。

## CI 重复验证

`Host and network integration` 运行 `TestCenterTwoAgentsLifecycle`，使用真实 CLI
子进程建立一个 Center 和两个 Agent。每个进程使用独立临时数据目录，监听
loopback，注册与管理操作经过正式 HTTP API；不安装宿主 systemd Agent，
不需要生产凭据、PVE 或新增依赖。普通 Go 测试跳过此项，由 CI 专用步骤启用。

验证在线永久移除被拒绝、正常停用删除、目标进程停止后自然离线、名称确认、
永久移除与 Center 重启后的结果、旧凭据和旧 Agent 重启不能复活节点。
对照 Agent 的身份保留且心跳持续前进。子进程、认证材料和数据库在退出时清理，
不上传 Actions artifacts。

该用例针对空白节点的控制流程；Glivela 冻结历史与迁移仍由 Center Go 用例验证。
它不等同于真实主机关机、应用卸载、浏览器操作或外部 Headscale/Tunnel/DNS 验收。
